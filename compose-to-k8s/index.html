Compose to Kubernetes migration

A real migration of a multi-service app from Docker Compose to Kubernetes, documented from a clean environment through cutover and rollback.

Status: Final stages

KubernetesDocker ComposeKomposeKustomize

The app

A voting application with five services: vote, result, worker, Redis and PostgreSQL. It is based on Docker’s open-source example-voting-app (Apache-2.0).

How the repo is organized

compose-to-k8s-migration/
legacy-compose/    the Compose file, the "before"
k8s-kompose-raw/   unedited Kompose 1.38.0 output
k8s/               hand-corrected manifests
docs/              one write-up per phase

Applied with kubectl apply -k k8s/

What I changed after Kompose

Kompose gave a starting point, and I kept its raw output unedited next to my corrected version so the two can be compared. The corrected manifests add a namespace, a Secret for the database credentials, an Ingress and a Kustomize file, and run the database as a StatefulSet.
